# 游戏审美 —— 量表、品类档案、资产量表

游戏美术首先看**玩家能不能玩**，其次才看是否美、是否令人记住。一帧绝美但藏住了敌人的画面就是 P0。本文件适用于任何游戏图像：截图、主视觉、商店胶囊图、图标、UI 界面、概念图、特效、精灵图集、横幅。配合 `game-workflows.md` 和 `scripts/review_image.py --type <游戏类型> --genre <品类>` 使用。

## 1. 通用量表（每项 1–10 分）

锚点：**9–10** 可直接上线的 3A/头部独立品质，处处可见有意的选择 · **7–8** 扎实，有小的不一致 · **5–6** 能用但普通或杂乱 · **3–4** 可读性或统一性问题影响游玩/营销 · **1–2** 损坏。

| # | 维度 | 9–10 分的样子 | 3–4 分的样子 | 快速测试 |
|---|---|---|---|---|
| G1 | **可读性与剪影** | 每个与玩法相关的形状（玩家、敌人、拾取物、危险物）涂黑后仍可辨认；不同角色/职业各有区别 | 角色与道具混在一起；成群时剪影粘连 | 白底上把主体涂黑；看 `grayscale.png` 中的 Otsu 蒙版 |
| G2 | **明度与色彩层级** | 3–4 个清晰的明度组；最亮/最饱和 = 最重要；背景被压进窄明度带 | 处处平均中灰；高光零散；背景和前景一样忙 | 灰度 + 三值色调分离；眯眼看 |
| G3 | **玩法优先的清晰度** | 玩家总能在 < 0.5 秒内被找到；敌/友/中立用颜色 + 形状编码；可交互物共享一种提示语言（描边、发光、颜色） | 可交互物看起来像装饰；敌方弹幕与背景特效同色 | 2 秒内回答“我在哪 / 什么伤害我 / 我能用什么” |
| G4 | **美术方向统一** | 角色、场景、UI、特效共享一套渲染规则（形状语言、边缘处理、材质、笔触、配色） | 素材商店大杂烩；写实道具挨着卡通角色；UI 像来自另一款游戏 | 随机挑 4 个资产并排放 |
| G5 | **UI/HUD 清晰度与密度** | HUD 按边缘分组、网格一致、按尺寸/对比排优先级、中心留给游玩；密度符合品类 | 面板到处都是、5 种文字样式、关键信息与装饰信息同等权重 | HUD 覆盖率 %；大声读出优先级顺序 |
| G6 | **特效克制** | 特效强度 ∝ 玩法重要性；清晰的预兆 → 命中 → 消散；判定框与视觉一致 | 粒子浓汤；大招看起来像普攻；泛光遮住敌人 | 战斗中定格；数一数争抢注意力的亮点 |
| G7 | **光影与氛围** | 光线引导路径与焦点；大气透视区分纵深层次；情绪契合当下（色彩脚本） | 平板均匀的光；或暗到只能靠猜来玩 | 把图模糊：光是否仍指向目标？ |
| G8 | **角色与场景设计** | 强烈的形状语言契合性格/职能；细节成簇且有休息区；场景是舞台而非墙纸 | 细节均匀撒满（“处处细节 = 没有细节”）；千篇一律的盔甲/奇幻套装 | 细节密度图（thirds-overlay 热区） |
| G9 | **品牌 / 主视觉吸引力** | 一个标志性钩子（姿势、道具、颜色）在缩略图下仍令人记住；logo 融入画面；品类一眼可辨 | 什么都塞进去的拼贴；logo 不可读；可以是任何一款游戏 | 120×45 / 128 px 缩略图测试 |
| G10 | **技术完成度** | 边缘干净、纹素/像素密度一致、无拉伸贴图、无锯齿闪烁、UI 文字清晰 | 分辨率混杂、放大后模糊、压缩糊块、像素尺度混用 | 边缘放大 200%；像素画看精确色数 |
| G11 | **AI 痕迹与原创性** | 无生成痕迹；各视角设计一致；IP 安全 | 见 §5 | §5 清单 |

总分 = 0.4 × 指标分（脚本）+ 0.6 × 视觉分。有任一 P0 则总分上限 59。

**P0**（阻断游玩或上架）：玩家/敌人不可读；关键 HUD 不可读或被遮挡；胶囊图标题在 120×45 下不可读；违反商店规则（Steam 基础胶囊图：只能有美术 + 游戏名 + 官方副标题——不得有评分、奖项、折扣或 CTA 文字）；比例/尺寸错误；主角出现 AI 解剖错误。**P1**：明度结构浑浊、配色无主色、HUD 杂乱、风格不一、特效噪声、像素尺度混用。**P2**：打磨——边缘清理、色温漂移、细小间距。

## 3. 品类档案

格式：**权重调整**（上调 ×1.5 的维度）· **配色/明度** · **HUD 惯例** · **常见错误** → **建议**。数字目标对应 `review_image.py` 中的 `--genre` 键（RMS 明度对比区间 / 最大显著色数 / 最大边缘 HUD 覆盖率）。

### RPG
- **欧美 RPG**（`rpg-western`；40–75 / 7 / 25%）· ↑G4 G7 G8 · 写实低饱和材质，一个魔法/危险强调色，暖色火把 vs 冷色环境光。HUD：头像 + 队伍在角落，快捷栏底部居中，小地图右上；菜单可带叙事质感（羊皮纸、皮革）但须可读。错误：棕灰一片；战利品图标不可读；对话框挡脸 → 给场景划分明度组，稀有度颜色用在边框而非整个图标，正文 24px 以上。
- **JRPG**（`jrpg`；45–85 / 8 / 30%）· ↑G1 G9 · 更高饱和度、赛璐璐/动画着色，鲜明的角色颜色对比更柔和的背景。HUD：行动顺序条、指令菜单；风格化菜单（Persona 式斜切）只要层级成立即可接受。错误：全马卡龙色 = 没有焦点；菜单风格压过可读性 → 每个角色一个主色相，在灰度下测试菜单。
- **ARPG / 刷宝**（`arpg`；45–85 / 7 / 25%）· ↑G1 G3 G6 · 暗色地面、明亮技能，怪物与地面至少差 2 个明度档；战利品稀有度颜色编码（灰/白/蓝/黄/橙…）严格一致。HUD：血/资源球或条在底部两角，技能栏居中。错误：范围技能刷屏遮住敌人预警 → 限制特效透明度，敌人预警置于最上层并用独特颜色（红/橙）。

### MOBA（`moba`；45–85 / 8 / 25%）
↑G1 G3 G6。地图中低饱和，英雄/技能特效高对比；队伍色（友方蓝 / 敌方红）绝不被皮肤覆盖；特效重要性分档 = 玩法影响（大招 > 控制 > 普攻），判定框边缘可见（Riot 的清晰度准则）。HUD：小地图在角落，技能栏底部居中，记分板顶部。错误：皮肤改变剪影或技能形状；泛光盖住地形 → 皮肤“清晰度对等”，地面贴花边缘清晰。

### FPS/TPS 射击（`shooter`；35–80 / 6 / 15%）
↑G1 G3 G5。敌人对比度必须高于环境（轮廓光、明度分离），交战距离上环境细节为低频；准星区干净。HUD：生命/护甲左下，弹药右下，极简；沉浸式单机可用叙事内 HUD，竞技需要清晰的非叙事 HUD。错误：迷彩写实让敌人隐身；全屏后处理特效 → 把高饱和色相留给威胁/目标。

### 大逃杀（`battle-royale`；40–80 / 7 / 20%）
↑G1 G3。200 米外可读：人物与植被靠明度而非仅靠色相区分；安全区/风暴颜色唯一；战利品稀有度远处可见。HUD：小地图 + 缩圈计时右上，小队左下，背包紧凑。错误：起伪装作用的外观 → 限制暗色/与植被同色的皮肤，或加轮廓光。

### 开放世界（`open-world`；35–75 / 7 / 15%）
↑G7 G8 G9。大气透视（近：更暗/更饱和；远：更亮/更冷/更灰），远处可见的地标剪影（“weenies”），按区域/时段编写色彩脚本。HUD 极简且可隐藏；顶部罗盘条或小地图。错误：图标铺满地图；植被均匀噪声 → 细节成簇，用明度开辟视觉路径。

### 2D 平台跳跃 / 银河城（`platformer`；45–90 / 7 / 15%）
↑G1 G3。可行走表面与背景清楚分离（明度、饱和度、描边）；前/中/后 3 层，背景对比被压缩；危险物共享一种形状/颜色语言（尖刺、红色）。HUD 很小，左上。错误：装饰性前景遮挡玩家；背景和平台一样高对比 → 视差层对比 −30–50%，后景去饱和。

### 像素风（`pixel`；45–95 / 16 / 20%）
↑G4 G10。有限调色板（常为 16–32 色，色阶带色相偏移），单一一致的像素尺度，最近邻整数倍缩放。脚本：`unique_colors_exact`（干净时 ≤ 64–256），`pixel_run_mode` = 放大倍数。错误：像素大小混用、旋转/亚像素精灵、双线性模糊、“枕头式着色”、AI “伪像素”噪声 → 以原生分辨率重绘，强制调色板，检查游程长度。

### 二次元 / 抽卡（`gacha`；45–85 / 8 / 35%）
↑G8 G9 G4。角色立绘就是产品：脸/眼是焦点，线稿干净，各卡池渲染一致；稀有度颜色（金/紫/蓝）一致；UI 华丽但分层（货币右上、活动左侧栏、主 CTA 右下）。错误：UI 过载（到处红点）、不同画师线宽不一、AI 手/头发错误 → 制定线稿/着色规范表，限制同时出现的角标数量。

### SLG / 4X 策略（`slg`；35–70 / 8 / 40%）
↑G5 G3。只要层级严格，高信息密度没问题：地图低饱和，阵营/单位高饱和，资源靠**图标形状 + 颜色**区分；每个缩放级别都可读（LOD 图标）。错误：面板同等权重、数字过小、只靠颜色区分阵营 → 等宽数字、阵营颜色 + 徽记、随缩放变化的细节。

### 卡牌 / CCG（`card`；45–85 / 8 / 40%）
↑G1 G4 G5。卡框体系一致；费用/攻击/生命数字最高优先（高对比、粗体）；插画在手牌尺寸（约 120 px 高）下可读；稀有度/阵营用卡框颜色 + 宝石形状编码。错误：文字背后的插画太忙；画师风格不一 → 卡牌文字放在实色底板上，美术需求附焦点区域蒙版。

### 休闲 / 解谜 / 三消（`casual`；40–85 / 8 / 30%）
↑G1 G3 G9。高饱和没问题，但每种棋子要双重编码（色相 + 形状）以照顾色弱玩家；圆润的形状语言；大而好点的按钮；棋盘与背景强分离。错误：糖果色一切平等；背景与棋盘抢戏 → 背景模糊/压暗，加棋盘边框。

### 放置 / 增量（`idle`；40–80 / 7 / 45%）
↑G5。数字层级（主货币最大），买得起/买不起状态一目了然，长时间游玩舒适（不要持续闪烁）。错误：红点刷屏、大数字未格式化 → 后缀记法（K/M/B 或 万/亿），放置动画低调。

### 恐怖（`horror`；25–70 / 5 / 10%）
↑G7 G3。低调光、大块暗部，但关键物体和路径仍可读（光池、轮廓光）；一个警示色相（血红、病绿）；用雾表现纵深。HUD 极简/叙事内。错误：纯黑死黑（clip_dark > 30%）把一切藏起来；惊吓特效噪声 → 阴影保持在明度 10–20 而不是 0，照亮路径。

### 竞速（`racing`；40–85 / 7 / 20%）
↑G3 G6。赛道边缘与路面对比；运动模糊只在周边；车辆与天空/赛道可区分；速度感靠拖影、视野。HUD：速度/转速右下，名次/圈数左上，小地图。错误：刹车区出现泛光/镜头光晕 → 弯心处限制后处理。

### 体育（`sports`；40–80 / 7 / 20%）
↑G1 G5。两队队服在色相**和明度**上互斥；场地中性；球/冰球对比度最高；左上角转播式比分条。错误：队服相近；记分板杂乱 → 队服冲突规则、转播模板。

### Roguelike / Roguelite（`roguelike`；45–90 / 7 / 25%）
↑G1 G3 G6。弹幕/预警层始终置顶并使用独特色相；房间地面压缩明度；祝福/遗物靠图标形状区分；每个生态在不同局之间保持色彩识别。错误：弹幕浓汤；遗物图标相似 → 敌方弹幕高饱和暖色，玩家特效冷色/去饱和。

### MMO（`mmo`；40–75 / 8 / 40%）
↑G4 G5。HUD 密集但默认布局分组；人群中名字牌可读；套装在同一语言内设计（避免小丑装混搭；幻化有帮助）。错误：默认 20 条快捷栏；外包资产不一致 → UI 布局预设，含材质/形状规则的美术圣经。

### 武侠 / 仙侠 中式风格（`wuxia`；35–80 / 6 / 30%）
↑G4 G7 G9。传统矿物颜料配色（石青、石绿、朱砂、赭石、月白、藤黄），云雾分层，用飘动的衣纹线表现动势；建筑符合朝代细节。书法字体只用于标题/logo，UI 正文用可读的无衬线/衬线（思源宋体/黑体）。错误：处处泛滥的“中国红 + 金”；仙侠粒子光效过载；道具朝代错乱；UI 满屏书法 → 克制的配色、留白、一个主色。

### 水墨风（`ink`；40–95 / 4 / 20%）
↑G2 G4。明度就是一切：以“墨分五色”（焦/浓/重/淡/清）作为明度结构；留白 ≥ 30%；一个朱红点题（印章、太阳、血）；边缘用枯笔质感，湿染表现纵深。错误：数码笔刷纹理均匀、灰成一片没有焦墨点睛、颜色太多 → 强制 3–5 级墨色 + 1 红，让纸面透出来。

## 4. 资产类型量表（叠加在通用维度之上）

| 资产 | 必须通过 | 典型失败 |
|---|---|---|
| **游戏内截图**（商店/App Store） | 展示真实玩法（Apple 2.3.3：应用使用中的画面，不只是标题图）；玩家 + 目标可读；HUD 不遮挡动作；前 1–3 张卖出核心循环 | 用菜单/加载画面当截图；UI 调试文字；4K 细节在商店尺寸下看不见 |
| **主视觉 / 海报** | 一个焦点主角、强剪影 + 明度设计、留出 logo 空间、品类一眼可辨、缩到 320×180 仍成立 | 角色拼盘；logo 贴在繁杂区域；没有明度层级 |
| **商店胶囊图 / 图标** | Steam 小胶囊图 462×174 会被自动缩放到 184×69 和 120×45——logo 必须仍可读，可使用不同于头图的美术；基础胶囊图只含美术 + 游戏名 + 官方副标题；图标：一个形状、2–3 个明度、无小字 | 标题字太细、多个角色、与 Steam 深蓝 `#1b2838` 对比低、评测引语/奖项 |
| **UI 界面** | 网格、字号 ≤ 3–4 档、主操作清晰、状态完整、图标风格一致、留出本地化空间（CJK +30% 宽度） | 装饰压过功能、边框不一致、只靠颜色区分状态 |
| **角色概念** | 剪影说明职能/性格；形状语言（圆=友好、方=稳固、三角=危险）；细节成簇 + 休息区；三视图一致 | 处处细节、千篇一律的盔甲、在游戏尺度下不可读 |
| **场景概念** | 清晰的构图路径、前/中/后景明度、光作为导航、地标、标出可游玩空间 | 只有绘景之美却没有可玩空间；均匀噪声 |
| **特效** | 预兆→命中→消散，形状与判定框一致，强度 ∝ 重要性，按队伍/元素着色，在所有生态上都可读 | 泛光浓汤、透明叠加遮住敌人、残留过久 |
| **精灵 / 像素图集** | 像素尺度 + 调色板一致、帧对位（无抖动）、1× 下可读、描边/选择性描边干净 | 分辨率混杂、对透明背景做了抗锯齿、孤立像素 |
| **营销横幅** | 平台安全区、logo + 一个钩子 +（允许时）一个 CTA、移动端可读、与主视觉体系一致 | 文字墙、裁到脸、Steam 基础资产上出现违规宣称/评分 |

## 5. 游戏美术的 AI 痕迹检查
- 手/手指、武器握持、左右不对应的对称装备、消失的腰带/绑带。
- UI、招牌、logo 上的乱码；“中文”书法中的伪字形。
- 不同视角/帧之间设计不一致（服装变化、精灵帧中多出的肢体）。
- “万物发光”：每条边都有轮廓光、到处是粒子尘埃、饱和 p95 ≥ 0.95。
- 无功能的细节：处处花纹、没有休息区、糊状微噪声（shape_edge_retention 低而 edge density 高）。
- 伪像素画：非整数像素网格、上千种精确色、边缘模糊。
- 场景中的透视/比例错误；漂浮的道具；无法平铺的图块。
- 风格漂移到与某位在世艺术家或现有 IP 相似 → 原创性/法律风险。

## 6. 指标区间（review_image.py 游戏类型）

| 指标 | 健康 | 需关注 |
|---|---|---|
| `value_bands` 最大档 | ≤ 0.70（低调恐怖/水墨可达 0.85） | > 0.85 → P1 明度单调 |
| `value_levels_used_5` | 3–5 | ≤ 2 |
| `figure_ground_gap`（Otsu 两类均值差） | ≥ 80 | < 60 → P1 |
| `shape_edge_retention`（4× 模糊后保留的边缘） | ≥ 0.40 | < 0.30 → 微细节噪声、大形弱 |
| `hud_edge_coverage_est` | ≤ 品类上限（10–45%） | 超出 → 杂乱 |
| `hud_center_clutter_est` | < 0.08 | > 0.15 → UI 侵占游玩区 |
| `color_bins_95pct`（5-bit） | 风格化 ≤ 600，写实 ≤ 3000 | 风格化美术上非常高 = 噪声 |
| `unique_colors_exact`（像素/精灵） | ≤ 64–256 | > 256 → 插值缩放/AI 像素画 |
| 缩略图 `contrast_rms` | ≥ 40 | 胶囊图/图标/主视觉 < 35 → P0 |
| 缩略图 `contrast_retention` | ≥ 0.85 | 胶囊图/图标 < 0.75 → P0 |

所有指标都是代理；HUD 和剪影估计会被建筑（直线）或繁杂纹理骗过。务必亲自看 `grayscale.png` 和 `thumbnail.png`。
