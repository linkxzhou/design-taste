# 重新设计 / 优化现有 UI

原则：**升级外观，不破坏行为。** 除非用户另有要求，保持路由、数据、props 和测试不变。

## 流程
1. **盘点** —— 技术栈、CSS 方案、组件库、现有 token、品牌资产。尽可能截图记录现状。
2. **审查** —— 运行 `audit.md` 中的检查；列出带数字的 P0/P1/P2。
3. **方向** —— 写下方向块（`direction.md`）。除非被要求换品牌，保留品牌资产（logo、主色）。
4. **先做 token** —— 把字面量合并进三层体系（`tokens.md`）。仅这一步就能修复大部分不一致。
5. **全局层** —— 字号尺度、基础颜色、间距节奏、圆角/阴影族。
6. **组件** —— 按钮、输入框、卡片、导航、表格：状态、尺寸、焦点。
7. **布局** —— 把通用区块（Hero + 3 张卡片、一切居中）改造成服务于内容的构图。
8. **打磨** —— 动效、文案、空/错误/加载状态、图像。
9. **验证** —— 重新运行可量化检查；对比前后数字；3 种宽度截图；运行现有测试/构建。

## 规则
- 小步、可评审；按层拆分 diff。
- 不要为了外观更换框架或引入重型依赖。
- 未经询问，不要为了“更干净”删除功能或内容。
- 变体：“更大胆” = 更强的对比/尺度/颜色投入；“更安静” = 更少颜色、更少装饰、更多留白；“提炼” = 不断删减元素，直到剩下的每一个都物有所值。
- 汇报：改了什么、前后指标、哪些延后处理。
